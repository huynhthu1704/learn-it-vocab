# Plan: onboard Learn IT Vocab to the Compass Framework v1.1

Requirements: none yet (framework install; the product's existing features are not back-filled as requirements)
Intent: the Product Owner asked to onboard this project to Compass, following the Compass portal and the
Compass Framework (huynhthu1704/compass) and the onboarded travel-map repo.

## Files
- AGENTS.md, CLAUDE.md, compass/** (generated by the portal's `frameworkFiles(project, { starter: false })`)
- .claude/settings.json, .github/workflows/compass-ci.yml, .github/pull_request_template.md, .github/ISSUE_TEMPLATE/*
- package.json (test script only, no dependency change), tests/words.test.mjs, .gitignore

## Steps
- Generate the framework files with the portal's own generator, so they match a portal install exactly.
- Fit them to this repo: no compass-deploy.yml (Pages serves main, ADR-001); CI fails when the committed build
  output is stale; protect firestore.rules and src/firebase-config.js; exempt the public Firebase web key from the
  secret scan (ADR-006); add `npm run build` to the commands.
- Back-fill ADR-001…006 from the README and git history.
- Add `npm test` with integrity checks of words.json.

## Risks
- Pages may be set to deploy from GitHub Actions instead of the branch: then nothing changes, since no deploy workflow is added.
- The back-filled ADRs may not match the Product Owner's view: they say so and need the PO's confirmation.
- The guardrails apply to later PRs (max 12 files, plan before code, protected paths need the `human-approved` label).

## Proof
- `node compass/check-spec.mjs` passes; `npm test` passes; `npm run build` leaves no diff.
- `node compass/check-guardrails.mjs main` runs on this branch.
- The guard-edit hook blocks a protected path and lets a normal file through.
