# Plan: turn off Jekyll on GitHub Pages and tidy the agent docs

Requirements: none (site hosting and docs; no product behaviour changes)
Intent: the Product Owner asked for the follow-ups from the independent review of #2: add `.nojekyll` and fix the
three doc nits (branch pattern in AGENTS.md, duplicate build text in CLAUDE.md, guardrails command against origin/main).
Decision: ADR-007 (GitHub Pages serves the site without Jekyll).

## Files
- `.nojekyll` (new, empty)
- `AGENTS.md` (step 4 branch pattern; guardrails command)
- `CLAUDE.md` (one build bullet, guardrails command, branch rule carries the squash-merge reason, drop duplicate lesson)
- `compass/handover.md` (Developer row branch pattern)
- `compass/spec.json`, `compass/decisions.md` (ADR-007)
- `compass/plans/nojekyll-and-agent-docs.md` (this plan)

## Steps
- Add an empty `.nojekyll` at the repo root so Pages serves the committed files without running Jekyll.
- Point AGENTS.md step 4 and the handover's Developer row to `<type>/<short-description>` (CLAUDE.md → Git branches),
  and drop the "This replaces…" note from CLAUDE.md.
- Fold the Building section into the `npm run build` bullet; keep the squash-merge reason on the branch rule and
  drop the duplicate lesson.
- Run the guardrails check with no argument: it defaults to `origin/main`, after `git fetch`.
- Record ADR-007 and regenerate `compass/decisions.md` with the portal's `decisionsMd`.

## Risks
- Without Jekyll, files and folders that start with `_` are also served; the repo has none.
- `compass/handover.md` is regenerated by the Compass portal on every spec commit, so its Developer row returns to
  the `compass/f-xxx` pattern until the portal's template changes. AGENTS.md and CLAUDE.md stay correct.

## Proof
- After merge, the GitHub Pages build for main succeeds and the live site loads.
- `node compass/check-spec.mjs`, `npm test` and `npm run build` (no diff) pass.
- `node compass/check-guardrails.mjs` passes on this branch: 7 files, no protected paths, plan present.
